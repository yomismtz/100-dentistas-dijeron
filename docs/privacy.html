DOCUMENTO DE PRIVACIDAD

Política de privacidad

Última actualización: 20 de septiembre de 2026.

Resumen: Así los Dentistas lo Dijeron funciona principalmente de forma local. No requiere una cuenta, no integra publicidad ni analítica propia y no transmite partidas a un servidor del proyecto. La voz es opcional y utiliza el servicio de reconocimiento instalado en Android; la aplicación no almacena grabaciones de audio.

1. Aplicación, responsable y contacto

Esta política corresponde a la aplicación educativa Así los Dentistas lo Dijeron (paquete Android asi.losdentistaslodijeron) y a su sitio oficial alojado mediante GitHub Pages. El editor de la aplicación será el titular de la ficha de Google Play donde se publique Así los Dentistas lo Dijeron.

Para consultas de privacidad puede utilizar el mecanismo público de contacto del proyecto en GitHub Issues. No publique datos personales, datos de pacientes ni información sensible en una incidencia pública; si la consulta requiere información privada, solicite primero un canal privado.

2. Datos tratados por la aplicación

La aplicación no requiere registro ni cuenta. Puede guardar localmente nombres de equipos, personajes, ajustes, historial reciente de preguntas, preguntas personalizadas, autoguardados, historial de sesiones, reportes académicos, paquetes de clase, torneos/campeonatos, códigos anónimos del modo investigación, resultados agregados de pretest/postest y metadatos editoriales.

El usuario decide qué nombres o códigos introduce. Para docencia o investigación se recomienda utilizar nombres de equipo y códigos que no identifiquen a estudiantes individuales.

3. Información que el proyecto no recopila en servidores propios

  • No requiere nombre legal, correo electrónico, teléfono ni dirección del estudiante.
  • No recopila ubicación precisa o aproximada.
  • No accede a contactos.
  • No integra publicidad, identificadores publicitarios ni analítica propia.
  • No transmite partidas, puntuaciones, reportes ni bancos de preguntas a un servidor operado por el proyecto.
  • No almacena grabaciones de voz.

4. Almacenamiento local, autoguardado y eliminación

Los datos descritos anteriormente se conservan localmente mediante el almacenamiento de la aplicación y su componente web. Android puede incluir determinados datos en copias de seguridad del sistema según la configuración del dispositivo. El proyecto no recibe esas copias.

Los datos locales pueden eliminarse borrando los datos de la aplicación desde Android o desinstalándola. Los historiales y configuraciones que cuenten con una opción de borrado dentro de la app también pueden eliminarse desde esa función.

5. Aula offline y red local

La aplicación puede crear un servidor HTTP y un canal WebSocket en la red local para pulsadores, respuestas individuales y control docente. Los dispositivos deben compartir la misma red Wi‑Fi o hotspot. La red puede funcionar sin salida a Internet.

Android exige el permiso INTERNET también para sockets de red local. Este permiso no significa que el proyecto envíe partidas a Internet. El panel docente se protege mediante un PIN local y el estado público de los equipos no incluye respuestas correctas ni referencias privadas mientras la ronda está activa.

La comunicación HTTP/WebSocket de este modo local no utiliza TLS. Debe usarse únicamente en una red Wi‑Fi/hotspot de confianza. Las respuestas individuales enviadas desde los teléfonos pueden llegar al dispositivo anfitrión y conservarse localmente en reportes o pretest/postest; no se envían al desarrollador.

6. Reconocimiento de voz y texto a voz

La respuesta por voz es opcional. Al activarla, la app abre el servicio de reconocimiento de voz instalado en Android mediante las interfaces del sistema. Así los Dentistas lo Dijeron no captura ni conserva directamente un archivo de audio.

El proveedor del reconocedor puede procesar la voz en el dispositivo o transmitirla a sus propios servidores, según el servicio instalado, los paquetes de idioma y la configuración del usuario. Ese tratamiento pertenece al proveedor del servicio de reconocimiento. La app recibe el texto reconocido y lo compara localmente con las respuestas del tablero.

La narración de preguntas utiliza el motor de texto a voz del sistema. La app envía al motor el texto que debe pronunciar; su funcionamiento depende del proveedor y la configuración de TTS instalada.

7. Imágenes clínicas importadas

El docente puede seleccionar voluntariamente una imagen mediante el selector de documentos de Android para asociarla a un reactivo. La app recibe únicamente el archivo que el usuario selecciona, limita el tipo a imágenes, lo procesa/redimensiona localmente y lo guarda en el almacenamiento local del reactivo.

El proyecto no recibe ni sube estas imágenes. El docente debe utilizar únicamente imágenes propias, anonimizadas o para las que tenga autorización. No deben importarse imágenes con nombres, números de expediente, rostros u otros identificadores de pacientes.

8. Modo investigación, pretest/postest y exportaciones

El modo investigación es opcional y utiliza un código de sesión anónimo. Puede registrar localmente grupo, nombres de equipos, puntuaciones, preguntas utilizadas, especialidad, dificultad, configuración y resultados agregados de pretest/postest.

El docente puede exportar CSV, archivos compatibles con Excel y tarjetas PNG mediante el selector de documentos de Android. La app escribe únicamente en la ubicación elegida por el usuario. El proyecto no recibe una copia.

9. Fuentes científicas y enlaces externos

Cuando el docente abre una fuente científica, el enlace se envía al navegador externo. A partir de ese momento se aplican las políticas del navegador y del sitio visitado. La aplicación no incorpora rastreadores propios para esos enlaces.

10. Sitio web y GitHub Pages

El sitio oficial está alojado mediante GitHub Pages. El proyecto no instala cookies propias de publicidad ni integra analítica. GitHub puede procesar información técnica, incluida la dirección IP, por razones operativas y de seguridad conforme a sus propias políticas.

11. Uso educativo y menores

La aplicación está destinada a docencia y repaso. No está diseñada para solicitar datos personales de menores. En entornos educativos deben utilizarse nombres de equipo, apodos no identificables o códigos en lugar de nombres completos de estudiantes.

12. Seguridad

El diseño minimiza servicios externos y mantiene el funcionamiento principal de forma local. El control docente utiliza PIN local y las respuestas correctas se bloquean durante la ronda. Ningún sistema puede garantizar seguridad absoluta.

13. Conservación

El proyecto no conserva en servidores propios las partidas, reportes, imágenes clínicas ni respuestas de voz. Los datos locales permanecen hasta que se sobrescriben, se borran desde la aplicación/sistema o se desinstala la app.

14. Cambios

Esta política se actualizará si cambian materialmente las funciones o prácticas de datos, por ejemplo si se incorporan cuentas, servicios en la nube, publicidad, analítica o nuevas integraciones externas.

15. Transparencia para Google Play

Esta página está destinada a utilizarse como URL pública de política de privacidad en Google Play. La sección “Seguridad de los datos” de Play Console debe mantenerse coherente con la versión distribuida y con las prácticas reales de los servicios de reconocimiento/TTS instalados en cada dispositivo.
